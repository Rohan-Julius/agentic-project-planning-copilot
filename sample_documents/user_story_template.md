# User Story Template

## Format

As a [persona],
I want [capability],
so that [business benefit].

## Acceptance Criteria

Given [initial condition]
When [action or event]
Then [expected result]

## Guidance

- Write the persona as a real role (e.g. "customer", "support agent"), never "user" alone.
- The capability should describe what the user can now do, not how it is implemented.
- The business benefit should be a real outcome, not a restatement of the capability.
- Include at least one acceptance criterion for the primary success path and one for a
  likely failure or edge case.
- Keep story point estimates as suggestions only — never present them as guaranteed
  estimates to stakeholders.
